## 验证覆盖还不够的部分

INT8 当前完成独立矩阵乘法、Softmax、标量 GELU 和一个 SIMD 背压探测，没有在提交版本中完成 MM→Softmax→GELU 整条流水线及 AXI-Lite/DMA 的系统回归。独立算子通过不能代替全系统通过。

baseline Softmax 只有理想浮点/量化格式对照，没有与 Exp/Ln 电路逐级对应的 Python 位精确模型。其格式参考与 RTL 的 MAE 为 0.003440791，RTL 与浮点目标的 MAE 为 0.003696663。数值是否满足应用要求需由模型精度确定，不能把分帧检查通过写成精度全部通过。

BF16 的完整生产参数验证尚未覆盖全部模式。现有 M=1 测试用于隔离单行算子，M=4 只补测四种模式的一组随机输入；新比特流也没有做新的上板回归。

## 软件和模型部署

INT8 板端驱动 mm.py 在 finally 中无条件释放缓冲区，超时分支没有先确认 DMA 停机。该异常恢复路径存在缓冲区所有权缺口，尚未完成板端恢复验证；通用 Skill 中的隔离处理不会自动修复这份独立驱动。

INT8 的 DMA 长度寄存器为 16 位，单次字节数需落在有效范围内。192×768 个 INT8 权重为 147,456 字节，超过单次传输容量。直接拆成多次传输会带来多次 TLAST，而 MM_in_buffer 的地址控制会受 TLAST 影响，需要硬件协议或 DMA 方案配合。

输入/输出宽度的分块计数为 5 位，每块 16 个元素，运行时最多表示 31 块，即 496 列；768 列还会超出计数字段。2400 拍缓存深度也需逐项校验。驱动目前只检查 16 对齐，尚未完整校验寄存器位宽、缓存容量和 DMA 长度。

RTL 已有 op_mode 和周期计数寄存器，INT8 Python 驱动尚未封装这部分接口。原 validate_acc_iscas.py 面向候选算法，与默认 baseline 模式不能混用。需要统一驱动入口、模式选择、错误信息和计时口径。

原 INT8 的 assets 目录为空，缺少 ViT 权重、输入与参考输出。完整 ViT 推理目前只有软件基线和分开的算子测试，没有全网络 FPGA 部署与任务精度结果。

INT8 与 BF16 当前共用提交目录，分别构建和加载；单比特流双精度选择、统一的软件 API、同任务同尺寸下的精度与性能比较尚未实现。

## 验证范围

当前提供算子与组合测试、既有实现报告和固定输入的 BF16 板测日志。完整模型部署、任务精度、功耗、同任务同尺寸的 INT8/BF16 对比及新产物板端回归不在已有证据范围。通用技能已完成离线/模拟和独立回环构建验证，未完成新封装的真实上板与跨板运行。

## 工具告警与复测

构建日志仍有官方 PS7 预设的负 DQS 延迟告警，以及自定义 AXI-Stream 接口属性同步提示。没有通过修改官方 DDR 延迟来隐藏告警。布局布线后 setup、hold 和 DRC 错误检查已通过，告警的板端影响仍需在新产物复测中核对。

Vivado 在 Windows 下受路径长度限制。较长临时目录的首次迁移检查失败，改用短目录后两个目标均可重新建立；提交路径应保持简短。
