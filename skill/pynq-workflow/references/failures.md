# 故障定位与经验来源

这里只记录有观察或测试支撑的规则。工程观测摘要及源文件哈希在 ../validation/project_observations.json，软件负例在 scripts/test_skill.py。现象与原因分开写，尚未定位的根因不写成定论。

|现象/触发条件|先查什么|处理边界|来源及验证|
|---|---|---|---|
|Overlay 目标错误，旧目录混有 Z100 文件|BIT part、HWH DEVICE/PACKAGE/SPEEDGRADE、导出哈希|不只看文件名，也不只改 xpr 的 part|原 INT8 python 目录有 7z100 元数据；本工具检查真实 Z2 产物并拒绝错板负例|
|同板型却结果异常|bit/hwh 是否同次导出、IP 参数与控制脚本版本|相同目标不证明配套；不要通过重命名掩盖|同目标不同哈希的负例在下载前被拒绝|
|DMA 不完成|DMASR、实际长度、TLAST/TKEEP、ready/valid、复位及输入顺序|不先增加超时或重启；先保存状态|模拟超时/短帧测试；PYNQ DMA 文档对 TLAST 的约束|
|16 位长度字段传 65536 字节或更大|HWH 长度位宽和 shape×dtype 字节数|超过 BTT 上限拒绝；不能未经协议验证自动分段|现有 INT8 DMA 长度16位；超长负例在硬件访问前失败|
|分段后权重被覆盖/帧提前结束|每段 TLAST 是否重置地址或触发计算|分段需要核的协议支持，不是通用 DMA 修复|INT8 MM_in_buffer 的 TLAST 地址控制观察|
|宽度16对齐但大矩阵仍不支持|分块计数字段位宽、片上缓冲拍数、DMA 三种限制|各约束分别核对，不用单一对齐检查替代|INT8 5位块计数与2400拍缓存参数；通用契约不猜算法容量|
|ready=0 后 data/last/keep 改变|valid 及数据是否同拍保持，流水线是否可停顿|加弹性缓冲或停顿控制后再测，不能只看最终数量|INT8 SIMD GELU 32拍探测记录4次保持违例；此问题仍待修复|
|首行/首帧 NaN，后续看似正常|原始帧、复位、状态初始化、浮点IP流水线|保留失败；区分控制复位与真实重新初始化|既有 BF16 194组中15组失败，含首帧非有限值；本工具检出相应原始数据|
|全负输入某候选 Softmax 与模型不同|最大值初始化、有效范围、分母近似、实际综合模式|不把候选版本的结论套到默认实现|ISCAS串行94/100一致，并行100/100；默认综合为baseline|
|RTL 与量化参考一致，但浮点误差明显|Q 是算法模型还是格式参考；近似公式和量化点|逐位一致与数学精度分列|现有 Softmax 与 GELU 三值比较观察|
|近零参考使相对误差很大|最大绝对误差、零参考分支、应用容差|阈值预先声明，不能为消掉失败临时放宽|BF16 SiLU/GELU -16常量用例；零参考单元测试|
|超时后 freebuffer 导致后续异常|DMA 是否确认 HALTED，是否仍有在途访存|未确认就保留进程和所有权；恢复需板级方案|无法停机的模拟负例验证不释放；暂无物理故障恢复实测|
|时序通过但端到端失败|控制、分帧、缓存和接口语义|静态报告不能作为系统功能证明|两工程静态报告通过，但上述功能失败仍存在|
|换路径建立工程失败|绝对路径引用、Windows路径长度、外部IP依赖|用短路径重建；不用复制cache作复现证据|合并工程长路径曾失败，短路径重建通过|
|声称加速但计时不公平|ARM/桌面CPU、是否含上传和结果DMA、尺寸、精度|分别列出不同范围，不混算速度比|既有 BF16 板测含重复计算/首次加载两种口径|

排查输出应包含：现象、触发输入、已读状态、支持的推断、尚未知的信息和下一项最小验证。状态寄存器可能有读副作用，只读接口说明允许的项。
